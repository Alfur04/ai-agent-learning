## 快速开始

### 环境要求

- Python 3.10+
- DeepSeek API Key（[获取地址](https://platform.deepseek.com)）

### 安装依赖

```bash
pip install openai python-dotenv
```

### 配置 API Key

```bash
cd 01-chatbot
cp .env.example .env
```

然后打开 `.env`，把 `your_api_key_here` 换成你自己的 Key。

> `.env` 已被 `.gitignore` 忽略，不会被提交。

### 运行

```bash
python chat2.py
```

## 实现要点

- **上下文管理**：对话历史以列表形式保存在内存中，每轮把完整历史发送给模型。
  列表必须初始化在循环之外——若在循环内重建，每轮都会得到一个全新的空列表，模型随即「失忆」。
  用户消息在请求前追加，助手消息在响应后追加，两者缺一都会导致上下文不完整。

- **流式输出**：`stream=True` 使接口返回迭代器而非完整响应，需要逐块读取
  `chunk.choices[0].delta.content` 并拼接。
  两个关键点：首个数据块的 `content` 为 `None`（只携带角色信息），必须判空；
  拼接出的完整文本要单独保存到变量，否则只存在于屏幕输出，无法写回历史。

- **历史裁剪**：每轮发送完整历史会让 token 成本随轮数快速上升，并可能触及上下文窗口上限。
  策略是保留 `system` 消息 + 最近 N 条。
  实现细节：裁剪必须放在追加助手消息之后——若在追加用户消息后裁剪，非 system 消息为奇数条，
  取偶数长度的尾部会以 `assistant` 开头，产生不合法的对话结构。

- **输入处理**：所有输入在入口处统一 `strip()`，后续逻辑不再重复清洗，避免同一份数据出现多套标准；
  空输入直接跳过本轮，退出命令用元组 `in` 判断，兼容大小写与中英文写法。

- **配置与密钥管理**：API Key 通过 `.env` 读取，不写入源码；
  `.gitignore` 屏蔽 `.env`，仓库中仅保留不含真实密钥的 `.env.example` 作为模板。

- **结构设计**：客户端在模块级创建一次（多个函数可共享），对话状态封装在函数内部
  （每次调用都是独立的会话）；入口用 `if __name__ == "__main__"` 保护，
  便于后续被测试代码或其他模块导入而不触发执行。
